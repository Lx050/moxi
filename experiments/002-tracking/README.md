# 002：记忆时间尺度下的目标跟踪

001 显示不同历史确实会分开，但单看 1 秒与 30 秒的状态差异不能回答记忆对操控有多迟缓。本轮在同一组固定、带种子的输入目标序列上，比较直接映射与四档时间常数，先量出响应速度与跟踪误差的取舍。

这一步仍使用 001 的手工显式状态方程。它没有学出任何潜空间，也不预测下一动作或下一帧，不能称为世界模型。

## 实现与运行

- `protocol.json` 在运行前固定种子、30 Hz、6 个变化目标、4 秒驻留、最终 8 秒收敛尾段和 0 / 0.25 / 0.5 / 1 / 2 倍时间常数。每个条件都重置为同一首个目标，避免历史残留污染条件对照。
- `scripts/run-tracking-experiment.mjs` 生成一次确定性目标序列，并对五种配置逐帧记录状态、目标及误差。直接映射作为零滞后消融。把六个响应时间常数等比例缩放，单独检验它们如何改变跟踪。
- `npm run experiment:tracking` 生成报告、逐帧轨迹和哈希；`npm test` 覆盖命令确定性、直接映射准确性、尺度增加后的响应速度关系和状态边界。
- `npm run serve` 运行本地演示页面。真人、TouchDesigner、MediaPipe 相机与 AIGC 生成均未参与本轮。

## 事先确定的评估门槛

使用归一化 RMSE、10% 误差带内连续稳定至少 0.5 秒后的稳定时间、未在 4 秒内稳定的比例、相对指令变化量的最大过冲、状态边界和核心计算耗时。直接映射 RMSE 上限为 1e-12；候选记忆尺度须同时满足 RMSE ≤0.08、至少 80% 的可测转移在段内稳定、稳定时间 P95 ≤3 秒。未稳定的转移在 P95 中以 4 秒右删失值计入。至少一档候选通过才支持本轮的合成工程假设。

这些门槛只是这组合成阶跃任务的筛选标准。它们不能证明参与者偏好、姿态输入可用或作品控制感得到改善。离线核心更新耗时不是系统端到端延迟。

本次结果（6 次输入命令、5 个实际转移）：直接映射 RMSE 为 0；0.25 倍尺度 RMSE 为 0.0406、稳定率 100%、稳定时间 P95 为 1.3 秒；0.5 倍为 0.0578、100%、2.6 秒。两档都通过预设目标。1 倍尺度 RMSE 为 0.0779，但只有 20% 转移稳定；2 倍没有转移在 4 秒内稳定，RMSE 为 0.1019。所有条件观察到的归一化过冲为 0，符合本轮一阶单调响应方程。详细源哈希、轨迹及失败修复记录在 `results/`。

## 风险与下一步

突然阶跃覆盖稳定目标，但不代表真实、连续的书写动作；单一种子也不代表常见用户轨迹。最终 8 秒尾段比每个 4 秒目标段更长，因此单独检查逐步收敛。首个命令作为统一初始状态，未计为一次转移。

下一轮从通过的 0.25 倍设置出发，构造按输入序列分割的训练/留出数据，比较无动作预测、直接映射和小型动作条件状态转移模型的一步及自由滚动预测误差。如果模型只恢复当前状态方程，就记录为已学动作条件动力学基线；在潜在表示确实经训练且滚动预测经留出评估前，不宣称已经得到学习潜空间或世界模型。若没有尺度通过预设门槛，则先检查三个状态共用一组时间尺度是否造成不必要的拖尾。
